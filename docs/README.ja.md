# 会話フロート

**dsh-conversation-float** — **会話ビュー**を DSH の固定位置から摘み出し、フロートパネルに変えます。

フロートは **DSH 自身のもの**——右サイドバーと同じドックキットのフローティングパネルで、二つ目のブラウザウィンドウではありません。タスクバーには DSH の窓が一つだけです。中身は**本物の会話ビュー**（同じ列であって、描き直した複製ではない）なので、入力・スクロール・「会話／軌跡」の切り替え・コンポーザー・添付・ペルソナ選択はすべてネイティブのまま動きます。

## 使い方

**入口**：セッションタイトルバー右端の小さなウィンドウアイコン（*Conversation float*）。

1 回押すとフロートが開き、**DSH の UI はそのまま残ります**：両サイドバーが開き、フロートはその間に空いた場所の中央に置かれます。**同じボタン**をもう 1 回押すと DSH の UI が隠れてフロートだけになります（そのときツールチップは「DSH を隠す」から「DSH を表示」に変わります）。もう 1 回押すと UI が戻ります。フロートを閉じる・左サイドバーへ収める・右サイドバーへドッキングすると、サイドバーは自動で元の状態に戻ります。

フロートは**最初から大きい状態**（約 920×711、ウィンドウに合わせて伸縮）で開きます。ドックキット自身の `resizeFloat` を使うためです（`sidebarRight.require()` → `actions.resizeFloat(sessionId, paneId, rect)`、`paneId` はフロートの `data-dockkit-float` から取得）。大きくするだけで、すでに広げたフロートを縮めることはありません。

右サイドバーが畳まれていれば開く前に**自動で展開**されます（「サイドバーへ収める」行き先を作るため）。左サイドバーも同様です。畳まれているかは**幅を測って**判定するので、狭いウィンドウで畳みフラグが書かれることはありません。

**フロートを閉じる——あるいは隠れた状態から抜ける——と、サイドバーはフロートを開く前の配置に戻ります。** フロート表示中にあなた自身がサイドバーを閉じたり開いたりしていれば、その最後の配置が戻ります。隠れた状態から閉じたときも同じで、右列だけに絞ったウィンドウはそのまま右列だけです。「あなた自身」は自分の押下・キー入力のみを数え、開く方向も閉じる方向も同様です。DSH が狭いウィンドウで左サイドバーを畳む、隠れたサイドバーが再レイアウトされる、フロート自身を押す、といったことは数えません。以前の配置のスナップショットは、どのサイドバーにも触る前に一度だけ取り、フロート表示中に上書きされることはありません。

## 左・中央・右へドラッグ

フロートのタイトルバーを押し続けてドラッグします。**1.2 秒押し続けると**判定状態に入り、そこからプレビュー枠がポインタ下の帯に追従し、離した位置の帯へ落ちます。判定状態に入るのは 1 回のドラッグにつき一度だけなので、帯をまたいでも待ち直しはありません。1.2 秒未満で離すと何も起きません（誤操作で会話が動かないように）。

三つの帯はウィンドウの実際の列です：**左サイドバー**（フレーム第 0 列、現在 0..280）、**中央列**（280..680）、**右サイドバー**（`data-rightbar-col` の列、680..1097）。プレビュー枠は落ちる領域をそのまま同じ大きさで覆います。

| 落とし先 | 離したあと |
| --- | --- |
| **左** | フロートは**左サイドバーの引き出しへ収まります**。閉じるのではなく見えなくなるだけなので中央列は空いたまま。左サイドバーに**その会話の名前を持つ**行が増え、押すと戻ります |
| **中央** | フロートが閉じ、会話は中央列へ戻ります |
| **右** | 会話は**右サイドバーのページ**としてドッキングします（DSH ネイティブのタブで、「サイドバーへ戻す」と閉じるを備えます） |

左サイドバーの行は、実際にフロートを入れたあとだけ現れます。それ以前は左サイドバーは空のままで、常設の入口は作られません。行が持つのは収めた会話のタイトルで、プラグイン名ではありません。会話を切り替えてもタイトルは変わりません。行を押すと*その*会話へ戻り、そのフロートが再び表示されます。

**ドラッグしなくても構いません。** 左サイドバーの「その他」メニューに **会話をここへ収める**、右サイドバーのガイドカード「その他のツール」に **会話をここへ移す** があります。どちらも DSH の普通のメニュー行で、既存の行の下に並び、会話がすでにその側にあるときは自分から消えます。

## 仕組み（なぜ会話を描き直さないのか）

- 会話の DOM は**一つだけ**。プラグインは会話を載せた列をパネル本文へ移し（同一ドキュメント・同一 React ルート）、閉じる／ホストが変わるときに戻します。元の席が消えていれば中央列へ戻すのが保険です。
- **左へ収める**＝フロートのルートに目印を付けて隠す（`visibility`/`opacity`）。パネルは**閉じない**ので、中央列は空いたままにできます。
- **右へドック**＝タブを右サイドバーへ渡し（`openResource(..., { destination: 'sidebar' })`）、移動とドッキングは DSH に任せます。
- **ドックしたタブは本文を保持します**：タブ種別を `keepMounted` 付きで登録するため、右サイドバーの別タブへ切り替えても会話はそのタブの本文に残り、中央列へは戻りません。列が「現在表示中の本文」に従うのは、その会話が現在のセッションであるときだけです。別のセッションでは中央列が席に戻ります（従来どおり）。

## パフォーマンス

アニメーションフレームごとに測るのは最大 1 回、三つの帯は押した瞬間に一度だけ測ります。プレビュー枠は帯が実際に変わったときだけ描き直し、移動は `transform` です。以前の版はマウス移動のたびにレイアウトを測って 4 つのスタイルを書いていました。重かったのはそこであり、ドロップの判定ではありません。

## 既知の制限

- 会話のホストは常に一つ：左サイドバーの行は**入口**で、会話の二つ目の生きた複製ではありません。
- フロートはそれを開いたセッションのものです。別のセッションへ切り替えると会話はそのセッションの中央列へ戻り（そのセッション自身のフロートがあればそちらへ）、戻ってくるとこのセッションのフロートが再び現れます。
- 左サイドバーの行は、収めた会話の名前を持ち、別の会話を見ている間もその名前のままです。押すとその会話へ切り替わり、フロートを再表示します。いま見ている会話をフロートにする行ではありません。
- 引き出しに入る会話は**一つだけ**です。別の会話を収めると前のものが置き換えられます。置き換えられたフロートは「収納」の目印だけを失って普通のフロートに戻るので、左サイドバーに行が二つ並ぶことはありません。
- 引き出しからフロートを出すと、**収めたときの位置**に戻ります（左サイドバーに重なることがあります）。中央へは戻りません。
- これは DSH ウィンドウ内のフロートで、独立した OS ウィンドウではありません。
- DSH を再起動すると引き出しの状態は残らず、会話は中央列へ戻ります。

## フロートの移動

フロートは DSH 自身のドラッグで動きます。手がパネルに触れている間、プラグインは自分が覚えている位置を適用しません。ドラッグ中にその矩形を再適用することが、以前「最初の移動で引っぱり返される」原因でした。

## インストール

DSH **>= 0.2.2-rc.1** が必要です（このバンドルはこのバージョンで開発・検証しています）。

### npm から

```bash
npm i dsh-conversation-float
```

そのあと **profile の `package.json`** に登録します。両方必要です：

1. `dependencies` に `"dsh-conversation-float": "^0.1.4"` を追加
2. `dsh.profile.bundles` に `"dsh-conversation-float"` を追加（登録されて初めてプラグイン一覧に出て、切り替えできます）

### ソースから

1. ソースを任意の場所に置く
2. `<profile>/node_modules/dsh-conversation-float` へ junction でリンク
3. profile の `package.json` で `dependencies` に `"dsh-conversation-float": "link:<path>"`、`dsh.profile.bundles` に `"dsh-conversation-float"`
4. `client.js` はホットリロードされます。ホスト側（`index.js`）は空実装で、変えたときだけ再起動が必要です
