# 会话浮窗

**dsh-conversation-float** — 把**会话视图**从 DSH 的固定位置摘出来，变成一块浮窗。

浮窗是 **DSH 自己的**——右侧栏那套停靠套件的浮动面板，不是第二个浏览器窗口：任务栏里仍然只有 DSH 一个窗。浮窗里放的是**真会话视图**（是原来那一列，不是重画一份），所以打字、滚动、切「对话 / 轨迹」、输入框、附件、人设选择器全都是原生的。

## 怎么用

**入口**：会话标题栏右侧那枚窗口小图标（`会话浮窗`）。

点一下 → 浮窗弹出，**DSH 界面照常在**：两侧栏都展开，浮窗落在它们中间那块空地里。**同一枚按钮**再点一下才把 DSH 界面**隐藏**，整窗只剩浮窗（鼠标停留的提示这时从「隐藏 DSH 界面」变成「显示 DSH 界面」）；再点一下界面回来。浮窗关掉、放进左栏、停进右栏时，两侧栏会自己回到该有的样子。

浮窗**一打开就是大窗**（约 920×711，按窗口大小收放），做法是调 dock kit 自己的 `resizeFloat` 意图（`sidebarRight.require()` → `actions.resizeFloat(sessionId, paneId, rect)`，`paneId` 取浮窗上的 `data-dockkit-float`）。只放大、不缩小：你已经拉大的浮窗，它不会给你改小。

若右侧栏原本是收起的，开浮窗前会**自动展开**（好让浮窗的「收回到侧边栏」有地方可落）；左栏若收着，也会先展开——判定左栏是否收起是**量宽度**（窄窗口下不写收起标记）。

**关掉浮窗（以及从隐藏态返回）时，左右栏会摆回窗口原本的样子**：如果你在浮窗开着的时候**亲手**关过／开过某一栏，那就**以你最后一次的摆法为准**——从这个隐藏态关掉也一样，比如你把窗口收成「只留右栏」，关掉后仍是「只留右栏」。判断「亲手」只看你按在侧栏上的那一下或按键，开／关两个方向都算；DSH 自己在窄窗口里收左栏、隐藏的栏重新排版、以及点浮窗本身，都不算。开浮窗之前的快照只取一次，浮窗期间不会被中途的样子覆盖。

## 拖动浮窗

**按住顶栏满 1.2 秒**，这次拖动才进入判定状态——从那一刻起预览框跟着指针实时换带，松手就按当时所在的那一带落位。判定状态**整次拖动只进一次**：换到别的带不会重新等 1.2 秒。按不满 1.2 秒就松手 = 什么都不发生（防止手滑把会话挪走）。

三条带就是窗口真实的三块：**左栏**（框架第 0 列，当前 0..280）、**中栏**（280..680）、**右栏**（`data-rightbar-col` 那列，680..1097）。预览框覆盖的就是将要落进去的那一块，尺寸与它一致。

| 落点 | 松手之后 |
| --- | --- |
| **左** | 浮窗**收进左栏抽屉**：浮窗并没有关掉，只是看不见了，所以中栏**保持空着**；左栏多出一行 `会话浮窗`，点它浮窗回来 |
| **中** | 浮窗关掉，会话回到中栏原位置 |
| **右** | 会话作为**右侧栏的一个页面**停进去（DSH 原生页签，带自己的 `收回到侧边栏` 和关闭） |

左栏那一行只在「确实把浮窗放进去了」之后才存在；没放进去之前左栏是空的，不会常驻一个入口。

**不想拖也可以。** 左栏「更多」菜单里有 **会话收至此处**，右侧栏向导卡「更多工具」里有 **会话移至此处**。两行都是 DSH 的普通菜单行，排在官方那两行下面；会话已经在那一侧时，对应的那一行会自己消失。

## 它是怎么做的（为什么不重画会话）

- 会话只有**一份 DOM**：插件把承载会话的那一列搬进浮窗的正文（同一文档、同一 React 根），关闭／换宿主时再搬回原位；搬丢的兜底是「原位置没了就回中栏」。
- **收进左栏** = 给浮窗根节点打一个标记让它隐藏（`visibility`/`opacity`），**不关闭**面板——这就是中栏能一直空着的原因。
- **停到右栏** = 把这枚页签交给右侧栏（`openResource(..., { destination: 'sidebar' })`），由 DSH 自己搬运与停靠。
- **停进右栏的页签会保住正文**：页签类型注册时带 `keepMounted`，所以切到右侧栏的别的页签时，会话留在那一页的正文里，不会再被塞回中栏。只有当它所属的会话就是当前会话时，会话列才跟着「当前可见的那个正文」走；换成别的会话，中栏仍然是座位，与以前一致。

## 性能

拖动时**每次动画帧最多算一次**，三条带的尺寸在按下那一刻量好；预览框只在**真的换带**时才重画（用 `transform` 位移）。早期版本每次鼠标移动都量版面＋写四个样式，那才是「比 DSH 原生拖动静涩」的原因。

## 已知边界

- 会话只能有一个宿主：左栏那一行是**入口**，不会出现「左栏里也放着一份正在滚动的会话」。
- 浮窗属于打开它的那条会话：切到别的会话时，会话列回到那条会话的中栏（那条会话自己有浮窗就回到它自己的浮窗），切回来时这条会话的浮窗会重新出现。
- 只要还有会话处于收栏状态，左栏的「会话浮窗」入口就一直保留，不管你切到哪条会话。点它浮起的是你当前正在看的会话；当前会话正是被收栏的那条时，就是把它取回来。切回被收栏的会话时仍然显示抽屉状态：中栏留空、入口在。
- 从抽屉取出浮窗时，浮窗会出现在**当初放进去的位置**（可能压着左栏），不会自动回中。
- 这是 DSH 窗口内的浮窗，不是独立的系统窗口。
- 关掉 DSH 再开：抽屉状态不保留，会话正常回到中栏。

## 安装

需要 DSH **>= 0.2.2-rc.1**——本包就是对着这个版本开发与验证的。

### 从 npm（推荐）

```bash
npm i dsh-conversation-float
```

装完还要在 **profile 的 `package.json`** 里登记，两步缺一不可：

1. `dependencies` 里加 `"dsh-conversation-float": "^0.1.3"`
2. `dsh.profile.bundles` 里加 `"dsh-conversation-float"`——登记成 bundle 之后它才会出现在插件列表里，也才能被开关

### 从源码

1. 取源码到本地任意目录
2. 以 junction 挂到 `<profile 目录>/node_modules/dsh-conversation-float`
3. profile 的 `package.json`：`dependencies` 写 `"dsh-conversation-float": "link:<源码路径>"`，`dsh.profile.bundles` 里加 `"dsh-conversation-float"`
4. 客户端（`client.js`）改完**热更新**生效；宿主半（`index.js`）是空实现，改它才需要重启。
