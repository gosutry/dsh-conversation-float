# 会话浮窗

**dsh-conversation-float** 把 DSH 的会话变成 DSH 内部一块真正可浮动的窗口——不是第二个操作系统窗口。这块窗口可以浮在界面上方，可以收成左栏里的一行任务栏条目，也可以停靠进右侧栏。你打开插件页、自动化页和其他左栏入口时，会话依然可用。

## 你能得到什么

- **一键开启**：会话标题栏右侧的小窗口图标。
- **真实的会话**，不是重画一份：打字、滚动、Conversation/Trajectory 两个页签、输入框、附件和人设选择器都保持原生。
- **多个浮窗**，每个 Session 一个，每个在左栏各占一行。
- **一个只负责抬升窗口的任务栏**：点某条会话行会把对应浮窗抬到前面，绝不改变它背后的页面。
- **在非会话页面上也有完整会话**：打开 Plugins、Automations、Settings 或其他左栏入口时，活会话的浮窗仍留在屏幕上，带着它的标题栏、View 页签和输入框。页面则留在浮窗背后的中栏里。
- **三态入口按钮**：打开浮窗、隐藏 DSH 其余部分、把 DSH 其余部分调回来。
- **会自己消失的菜单行**：「会话收至此处」在窗口最小化后隐藏，「会话移至此处」在会话停靠到右侧后隐藏。

## 打开、最小化、关闭

点会话标题栏里的窗口图标。浮窗会以较大的尺寸打开（约 920×720，随窗口缩放），DSH 其余部分仍然可见，两侧栏都留在它让出的空间里。

同一个按钮在三种状态间循环：

1. 打开浮窗；
2. 隐藏 DSH 界面，只留浮窗；
3. 重新显示 DSH 界面。

关闭浮窗、把它最小化进左栏，或把它停靠进右侧栏时，两侧栏都会恢复到浮窗打开时记录的那套布局。这份快照只取一次，窗口开着期间不会被覆盖。浮窗开着时你对侧栏做的改动不会被跟踪。

窗口的 **—** 按钮把它最小化：窗口消失，但它在左栏的任务栏行还在。点那一行就能叫它回来。**✕** 按钮则彻底关闭：窗口和它那一行一起消失，会话回到中栏。

DSH 被隐藏时，按 **Escape** 可以调回界面。

## 移动会话

按住窗口标题栏拖动。按住不动 **1.2 秒**会激活投放带；标题栏变色，一个轮廓跟随指针所在的那条带，松手就把会话放到那里。还没到按住时长就松手则什么都不发生。触摸屏上，按住完成前移动超过 10 px，这次手势就仍按普通窗口拖动处理。

| 放到 | 结果 |
| --- | --- |
| **左侧栏** | 窗口被最小化进左栏。它没有被关闭；任务栏行是回去的入口。中栏保持空白。 |
| **中间** | 窗口关闭，会话回到中栏。 |
| **右侧栏** | 会话作为 DSH 原生页面停靠进右侧栏，带着 DSH 自己的收回和关闭控件。 |

左栏那一行显示的是该 Conversation 的标题，不是插件的名字。窗口去看别的 Conversation 时，这一行仍保持那个标题。点这一行只会显示并抬升那个窗口；它绝不会选中插件主面板，也不会把插件页或自动化页夺走。

**也可以不拖。** 左栏的 *More* 菜单里有 **会话收至此处**。右侧栏的引导里有 **会话移至此处**。会话已经在该位置时，对应那一行会自己隐藏。

## 会话之外的页面

当你打开 Plugins、Automations、Settings 或其他左栏入口时，会话列会退回中栏，好让页面能使用常规的三栏框架。活 Session 的浮窗仍留在屏幕上，并切换成一个**完整的本地会话**：会话标题栏、Conversation/Trajectory 页签和输入框。它不是一份只读记录。

页面在**浮窗背后**。把浮窗拖到一边就能操作页面。点该 Session 的任务栏行只会抬升浮窗；页面保持打开、不变。关闭页面，或正常回到会话，真实的会话列就交还给浮窗。

对于**不是**活会话的那个 Session，它的窗口仍显示只读记录。一条会话只有一个活输入框；输入框和 View 页签都属于活 Session。

## 多个窗口与任务栏

每个 Session 可以有一个浮窗。每个浮窗在左栏各占一行，按任务栏的方式排列。行以各自的 Session 命名。

- 点一行会**抬升那个窗口**。它不切换当前 Session，也不改变主面板。
- 非活窗口在最上层时会显示一枚 **切换到当前会话** 标签。点它会让那个 Session 变成活会话；窗口随后接管真实的会话列。
- 关掉一个窗口不会影响其他窗口。
- 会话任务栏行只是一个入口，永远不是会话的第二份活副本。

## 停靠进右侧栏

向右拖动，或使用 **会话移至此处**，就会把这个页签交给 DSH 的右侧栏。页签类型用 `keepMounted` 注册，所以切到右侧栏的别的页签时，会话仍留在自己的页签主体里。该 Session 活着时，这一列跟随屏幕上当前显示的那个保留主体；换成任何别的 Session，中栏又重新成为它的位置。

## 草稿与输入框

一个 Session 只有一个输入外壳和一个编辑器，而编辑器一次只能挂在一个 DOM 根上。当会话在中栏、窗口和右侧栏页面之间移动时，插件会把编辑器重新挂到屏幕上的输入框上，并把草稿写入器恢复到一个空槽位里。你看到的草稿就是发出去的草稿。

关闭浮窗不再靠点击另一个 View 页签来强制重挂。插件直接修好编辑器，所以窗口回到会话时不会闪过 Trajectory 或任何其他 View。

## 性能

每个动画帧最多做一次布局测量。三条投放带在按下时只测一次。依赖 DSH 提交变更的那些等待由帧驱动；插件**不保留任何 interval**，只在 DSH 本来就会引发的布局过程中做修复。轮廓只在带发生变化时重绘，并且用 `transform` 移动。

## 已知限制

- 浮窗在 **DSH 窗口内部**，不是独立的操作系统窗口。
- 一条会话**只有一个宿主**。任务栏行是入口，永远不是第二份活副本。
- 当 Session 不是活会话时，它的窗口显示**只读记录**：没有 View 页签，没有输入框。要打字就把它切到活会话。
- 非会话页面打开时，活浮窗保持一个完整的本地会话，但那个页面在**窗口背后**。浮窗不会自动缩成侧栏，也不会自己停靠。
- 浮窗属于打开它的那个 Session。切换 Session 会把会话交给新 Session 的中栏或它自己的浮窗；切回来时旧浮窗也回来。
- 重启 DSH 会清空浮窗和任务栏行。会话回到中栏。
- 输入框修复使用了几处 DSH 内部结构（输入框盒子背后的编辑器、会话输入外壳及其草稿槽位）。将来某个 DSH 版本改了这些名字时，行为会退回到旧样子，而不是崩溃。

## 安装

需要 DSH **>= 0.2.2-rc.1**。

### 从 npm 安装

    npm i dsh-conversation-float@0.3.0

然后在**profile 的 `package.json`** 里注册——两步都必须做：

1. 把 `"dsh-conversation-float": "^0.3.0"` 加到 `dependencies`；
2. 把 `"dsh-conversation-float"` 加到 profile 的 `dsh.profile.bundles` 列表。

只有注册为 bundle 的插件才会出现在插件列表里，也才能被开关。

### 从 tarball 安装

    dsh plugin add <path-to>/dsh-conversation-float-0.3.0.tgz

或者把 tarball 放进 profile，用 `file:` 依赖，再把包名加进 bundle 列表。

### 从源码安装

1. 把源码放在任意位置；
2. 软链到 `<profile>/node_modules/dsh-conversation-float`；
3. 给 profile 加一个 `link:` 依赖，并加上 bundle 名。

bundle 在启动时装配，所以安装或升级后要重启 DSH。
